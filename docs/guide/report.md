# 实验报告与提交规范

## 一、报告要求

实验报告在完成全部实验后统一撰写，不要求每个阶段单独撰写报告。每组提交一份报告，按实验部分组织内容，并参考《武汉大学计算机学院课程设计报告书写规范》（见下方附件）中的模板和格式要求。

报告重在把原理、设计、实现过程和结果表达清楚，不是越长越好。可以结合文字、流程图、结构图和表格说明，图表须有必要的标注和解释，避免重复叙述或堆砌源码；具体见[评分标准](./grading#三实验报告得分20)。

:::info[报告书写规范]
点击下载：[武汉大学计算机学院课程设计报告书写规范.doc](pathname:///word/武汉大学计算机学院课程设计报告书写规范.doc)
:::

报告中应至少包含以下内容：

- **实验内容**：本次实验的具体任务和实现目标
- **实验目的**：本次实验要达成的能力目标
- **实验原理**：涉及的编译理论，如正则表达式、有限自动机、LR 分析、SSA 形式、数据流分析等
- **设计思路**：整体架构设计、模块划分、数据结构选择
- **关键算法与流程描述**：核心算法的伪代码或流程图
- **评测结果**：结合平台提供的功能与性能评测结果，分析实现效果和不足；无需额外提交测试用例、测试输出或运行截图
- **分工**：小组各成员负责的模块以及贡献比例，参考格式如下：

  | 姓名 | 学号 | 负责模块 | 贡献比例 |
  | --- | --- | --- | --- |
  | 张三 | 20240001 | 词法分析器、语法分析器 | 35% |
  | 李四 | 20240002 | IR 生成、代码优化 | 35% |
  | 王五 | 20240003 | 目标代码生成、寄存器分配 | 30% |
  | 赵六 | 20240004 | 无 | 0% |
- **遇到的问题和解决思路**：遇到的典型问题与解决方案
- **心得体会**：实验总结与思考

报告中还应记录构建命令、运行命令，助教可能会构建运行。

## 二、提交方式

### 最终交付物

| 交付物 | 内容要求 |
| --- | --- |
| 源码与构建脚本 | 完整编译器源码，能在干净的 Linux 环境中从源码构建；仓库结构见[希冀提交与评测](./submission#一仓库必须包含的内容) |
| 设计说明 | 说明整体架构、模块接口与关键设计决策，可放在 `README.md`、`DESIGN.md` 或 `docs/` 中 |
| 实验报告 | 完成全部实验后统一撰写一份，按实验部分组织算法、数据结构、评测结果与问题分析 |
| 汇报 PPT | 10–15 页，说明编译器架构、关键实现、实验结果与不足 |

### 提交安排

实验代码按阶段上传到 Git 仓库，并按[希冀提交与评测](./submission#六提交到希冀平台)提供仓库地址、访问令牌和可选分支名，由评测平台自动拉取与编译。
实验报告与汇报 PPT 在第 15 周汇报展示时统一提交，报告使用助教另行提供的入口，不需要在每个阶段单独提交。阶段里程碑见[实验时间安排](./workflow#五时间安排)，汇报准备见[验收方式与提问范围](./workflow#四验收方式)。

提交代码时可参考以下步骤操作：

```bash
# 执行位置：WSL / Ubuntu 开发主机终端（编译器项目根目录）
# 1. 切到本次实验的分支
git checkout -b part1-lexer

# 2. 提交本次实验的代码
git add .
git commit -m "part1: 完成词法分析器"

# 3. 推送到远端并发起 PR
git push -u origin part1-lexer
```

在远程仓库上发起 Pull Request，标题格式为 `[Part1] 学号 姓名`。
