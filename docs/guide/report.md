# 实验报告与提交规范

## 一、报告要求

完成全部实验后，每组提交一份报告，按实验部分组织内容，须采用下方学院报告模板。

报告重在把原理、设计、实现过程和结果表达清楚，不是越长越好。可以结合文字、流程图、结构图和表格说明，图表须有必要的标注和解释，避免重复叙述或堆砌源码；具体见[评分标准](./grading#四实验报告得分20)。

:::info[实验报告模板]
[下载实验报告模板](pathname:///word/武汉大学计算机学院课程设计报告书写规范.doc)
:::

报告中应至少包含以下内容：

- **实验内容**：本次实验的具体任务和实现目标
- **实验目的**：本次实验要达成的能力目标
- **实验原理**：涉及的编译理论，如正则表达式、有限自动机、LR 分析、SSA 形式、数据流分析等
- **设计思路**：整体架构设计、模块划分、数据结构选择
- **关键算法与流程描述**：核心算法的伪代码或流程图
- **评测结果**：结合平台提供的功能与性能评测结果，分析实现效果和不足；无需额外提交测试用例、测试输出或运行截图
- **分工与个人贡献**：列出阶段分工、各成员负责的模块、具体贡献及贡献比例，参考格式如下：

  | 姓名 | 学号 | 负责模块 | 贡献比例 |
  | --- | --- | --- | --- |
  | 张三 | 20240001 | 词法分析器、语法分析器 | 35% |
  | 李四 | 20240002 | IR 生成、代码优化 | 35% |
  | 王五 | 20240003 | 目标代码生成、寄存器分配 | 30% |
  | 赵六 | 20240004 | 无 | 0% |

- **AI使用情况说明**：单列一节，写明使用的 AI 工具名称、涉及部分（如思路整理、代码生成与调试、文档润色）、验证方法，以及本人补充或修改的内容；未使用 AI 也须注明
- **遇到的问题和解决思路**：实现与分工合作中的典型问题、解决方案及尚未解决的问题
- **心得体会**：实验总结与思考

报告中还应记录构建命令、运行命令，助教可能会构建运行。

允许 AI 辅助，但每位成员须理解提交的代码、算法和文字，能独立说明原理、逻辑、实现过程及本人贡献；使用框架同样须能解释相关原理。阶段报告、最终报告及答辩均会检查，无法解释者扣除对应部分分数。

## 二、提交方式

### 最终交付物

| 交付物 | 内容要求 |
| --- | --- |
| 源码与构建脚本 | 完整编译器源码，能在干净的 Linux 环境中从源码构建；仓库结构见[希冀提交与评测](./submission#一仓库必须包含的内容) |
| 设计说明 | 说明整体架构、模块接口与关键设计决策，可放在 `README.md`、`DESIGN.md` 或 `docs/` 中 |
| 实验报告 | 完成全部实验后统一撰写一份，按实验部分组织算法、数据结构、评测结果与问题分析 |
| 汇报 PPT | 10–15 页，说明实验完成情况、关键实现、阶段分工与个人贡献、合作问题及解决思路、AI 使用情况 |

### 提交安排

实验代码按阶段上传到 Git 仓库，并按[希冀提交与评测](./submission#六提交到希冀平台)提供仓库地址、访问令牌和可选分支名，由评测平台自动拉取与编译。
第 12 周检查阶段进度，第 17 周检查完整实现并提交报告与汇报 PPT。报告提交入口由助教提供。每次自述 10 分钟、提问 10 分钟，共 20–30 分钟。具体见[实验时间安排](./workflow#五时间安排)和[验收方式](./workflow#四验收方式)。

提交代码时可参考以下步骤操作：

```bash
# 执行位置：WSL / Ubuntu 开发主机终端，编译器项目根目录
# 1. 切到本次实验的分支
git checkout -b part1-lexer

# 2. 提交本次实验的代码
git add .
git commit -m "part1: 完成词法分析器"

# 3. 推送到远端并发起 PR
git push -u origin part1-lexer
```

在远程仓库上发起 Pull Request，标题格式为 `[Part1] 学号 姓名`。
